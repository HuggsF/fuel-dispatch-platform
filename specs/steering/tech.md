# Tech steering — fuel-dispatch-platform

## Stack

| Concern | Choice | Notes |
| --- | --- | --- |
| Language | Java 21 (LTS) | Records, sealed types, pattern matching, virtual threads allowed |
| Framework | Spring Boot 3.x (latest stable 3.x at phase 00) | Enterprise standard. Upgrading to 4.x is a possible later ADR |
| Build | Maven multi-module + Maven Wrapper | Versions centralized in the parent POM (`dependencyManagement`) |
| dispatch-service web | Spring MVC | Blocking, transactional command side |
| dispatch-service data | PostgreSQL 16, Spring Data JPA, Flyway | `ddl-auto=validate`; schema only via Flyway |
| tracking-service web | Spring WebFlux | Reactive read side, SSE streaming |
| tracking-service data | MongoDB 7, Spring Data MongoDB Reactive | |
| Messaging | Apache Kafka (KRaft, image `apache/kafka`), Spring for Apache Kafka | JSON events, key = orderId |
| API docs | springdoc-openapi | Swagger UI on each service |
| Resilience | Resilience4j (Spring Boot 3 starter) | Circuit breaker, retry, time limiter |
| Observability | Spring Boot Actuator, Micrometer, Prometheus, Grafana | Dashboard versioned as JSON |
| Mapping | Hand-written mappers (no MapStruct) | Keeps adapters explicit and readable |
| Boilerplate | No Lombok | Use records and explicit code |

## Testing rules

| Layer | Tooling | What to test |
| --- | --- | --- |
| Domain | JUnit 5, AssertJ | Every rule and every valid/invalid transition |
| Application | JUnit 5, Mockito | Use cases orchestrate ports correctly; events go to outbox |
| Web adapters | `@WebMvcTest` / `@WebFluxTest` | Status codes, validation, ProblemDetail bodies |
| Persistence / messaging | Testcontainers (PostgreSQL, MongoDB, Kafka) | Real infrastructure, no H2 or embedded Kafka |
| Architecture | ArchUnit | Hexagonal dependency rules (see `structure.md`) |
| Coverage | JaCoCo | Build fails below 80% line coverage on `domain` and `application` |

Test naming: `methodOrBehaviour_condition_expectedResult` or `@DisplayName` sentences.
Test first: write the failing test, then the code.

## Conventions

- REST paths under `/api/v1`. JSON in camelCase. Instants in ISO-8601 UTC.
- Errors follow RFC 9457 (`ProblemDetail`), with a `code` property (e.g. `INVALID_TRANSITION`).
- IDs are UUIDs generated by the domain, not by the database.
- Configuration via `application.yml` + environment variables; no profiles beyond `default`, `test`, `docker`.
- Logs are structured (JSON in the `docker` profile) and include `orderId` when relevant.
- Formatting: Spotless with Google Java Format (AOSP style), checked in `verify`.
